# Privacy en security

## Uitgangspunt

Een buyer room kan persoonsgegevens en commerciële context bevatten. Behandel de oplossing daarom niet als een gewone openbare marketingpagina.

## Minimale gegevens

Verwerk alleen gegevens die nodig zijn voor opvolging:

- Naam
- Bedrijfsnaam
- Zakelijk e-mailadres
- Taal
- Gespreksnotitie
- Productinteresse
- Gewenste vervolgactie

Vermijd:

- Privégegevens
- Interne klantbeoordelingen op de openbare pagina
- Vertrouwelijke prijzen
- Contractafspraken
- Niet-openbare marges
- Gevoelige bedrijfsinformatie

## URL

Een moeilijk te raden URL is geen volledige beveiliging.

Gebruik daarom:

- Een willekeurige code in de slug
- Geen e-mailadres in de URL
- Geen volledige persoonsnaam in de URL
- Een vervaldatum
- Een verwijderproces

Voor gevoelige inhoud is extra toegangscontrole nodig.

## AI-gebruik

- Gebruik alleen een goedgekeurd AI-model
- Stuur zo weinig mogelijk persoonsgegevens mee
- Log geen volledige prompts wanneer dit niet nodig is
- Laat AI geen prijzen of beschikbaarheid verzinnen
- Laat sales altijd controleren voor publicatie

## Publicatie

Voor de eerste demo:

- Gebruik fictieve gegevens
- Zet de pagina niet in zoekmachines
- Voeg `noindex` toe
- Gebruik geen vertrouwelijke documenten

Voor een echte pilot:

- Leg bewaartermijnen vast
- Maak verwijderen mogelijk
- Controleer toestemming voor opvolging
- Leg vast wie publicatie mag goedkeuren
- Registreer welke versie is verstuurd

## Praktische checklist

- [ ] Alleen noodzakelijke gegevens opgeslagen
- [ ] Toestemming voor opvolging vastgelegd
- [ ] Buyer room bevat geen interne salesnotities
- [ ] URL bevat geen direct herleidbare gevoelige gegevens
- [ ] Pagina heeft een vervaldatum
- [ ] Pagina staat op `noindex`
- [ ] Sales heeft de inhoud gecontroleerd
- [ ] Verwijderprocedure is getest
